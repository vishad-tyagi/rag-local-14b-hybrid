03 · The Engines

Three pipelines, each with its own guardrails.

Every number below is lifted from the source, not rounded for marketing.

Hybrid retrieval, fused by rank

Dense FAISS search and lexical BM25 each return 5 candidates; weighted Reciprocal Rank Fusion merges them so exact IDs like ACCT-9001 and fuzzy policy language both surface.

vector 0.6 · bm25 0.4 · rrf_k 60 · final_k 5

SQL that can't hurt you

The LLM generates SQLite against a schema-aware prompt; output is stripped of markdown and chat tokens, validated as SELECT/WITH-only against a 12-keyword blocklist, and executed over a connection opened with mode=ro. Destructive requests are refused before generation even starts.

ensure_read_only_sql()is_destructive_sql_request()12 blocked keywords

Cypher with a safety net

Eight prompt patterns (A–H) teach the model entity discovery, path finding, and aggregation over the banking graph. If a generated query returns nothing, a deterministic fallback library of hand-written Cypher answers known shapes — branch lookups, merchant payments, alert→policy links.

_fallback_cypher()_ensure_read_only_cypher()graph_chain.py

A router that doesn't trust itself

AUTO mode asks the 14B model for routing JSON, then scans the raw output with JSONDecoder.raw_decode to find a valid object anywhere in the text. Parse failure triggers a keyword-scoring heuristic — so routing degrades gracefully instead of erroring.

_extract_json()_heuristic_route()_normalize_route()

Self-repairing queries

When generated SQL throws a SQLite error, the error text, the failed query, and the schema are fed back to the model for one repair attempt before failing — turning many would-be errors into answers.

_repair_sql()sqlite3.Error → retry

04 · Engineering Notes

The problems that didn't show up in the tutorial.

Running a quantized 14B model as a JSON router, SQL generator, and Cypher generator on one machine surfaces failure modes worth documenting honestly.

WAR STORY · 01

Special tokens leaking into streams

Qwen's <|im_end|> and <|endoftext|> tokens leaked into SSE responses and even into generated SQL, breaking both the UI and the parser.

fix: token stripping at every LLM boundary — answer(), stream_answer(), strip_markdown_sql() all scrub <|…|> patterns before anything downstream sees the text.
WAR STORY · 02

MLX's final chunk isn't text

mlx-lm's stream_generate ends each stream with a metadata object. Naively casting chunks to strings appended a Python repr to every streamed answer.

fix: duck-typed chunk handling — use response.text when present, pass strings through, drop everything else. (hf_models.py)
WAR STORY · 03

A 14B model is a chatty JSON API

The AUTO router needs strict JSON, but the model sometimes wraps it in prose or emits two objects. json.loads() on raw output failed often enough to matter.

fix: scan every "{" with JSONDecoder.raw_decode and take the last valid object; if none parses, fall back to the deterministic keyword router with confidence capped at 0.62.
UPGRADE PATH

Single retriever → hybrid fusion

V1 used pure vector search with k=4 — it missed exact-match questions about IDs like ALERT-5001 that embeddings treat as noise. The 7B→14B model upgrade and a retrieval rework landed together.

before: FAISS only, k=4, misses on exact IDs
after: FAISS k=5 + BM25 k=5 → weighted RRF (0.6/0.4), structured per-source prompt blocks, chunks 900→1200 chars
05 · Stack

Every piece earns its place.

MLX + mlx-lm
Apple-Silicon-native inference; runs a 4-bit 14B model on a laptop GPU with no server.
Qwen2.5-Coder-14B
Code-tuned weights generate cleaner SQL, Cypher, and routing JSON than general chat models.
FAISS
Fast local dense index; loads from disk in one call, no vector-DB service to babysit.
rank-bm25
Lexical recall for exact IDs and policy phrases that embeddings blur together.
all-MiniLM-L6-v2
384-dim embeddings, small enough to run on MPS alongside the 14B without contention.
LangChain
SQL chain + schema inspection + graph transformer reused instead of rebuilt.
SQLite (read-only URI)
The whole banking schema in one file; mode=ro makes the DB itself the last line of defense.
Neo4j
Relationship questions ("how is X connected to Y?") are graph traversals, not JOIN gymnastics.
Flask + SSE
Token-by-token streaming over plain HTTP — no websocket infrastructure for a local app.
06 · Where this skeleton goes

The pattern scales past the demo data.

01

On-prem compliance copilot

Banks can't ship AML cases to a cloud LLM. The same router + guarded engines pattern works over real core-banking schemas and policy manuals, fully inside the perimeter.

02

Internal docs × warehouse assistant

Swap the handbook for runbooks and the SQLite file for a read replica: one assistant that answers both "what's our rollback policy" and "how many incidents last quarter".

03

Fraud-investigation workbench

The graph engine's path queries ("connect this customer to this merchant") are the core move of investigation tooling — here with provenance, read-only guarantees, and fallbacks.

04

Air-gapped & regulated deployments

Healthcare, defense, legal: anywhere data can't leave the machine. Every dependency here installs from a lock file and runs offline after first model download.
